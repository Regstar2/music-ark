# v0.11-restore-upload-experimental

## Цель

Проверить возможность восстановления треков через загрузку локальных файлов в Яндекс Музыку.

## Главный результат версии

Появляется экспериментальный сценарий: оригинальный трек из Яндекс Музыки связывается с локальным файлом и потенциально с загруженной пользовательской версией.

## Входит

- исследование загрузки пользовательских треков;
- тестовая загрузка одного файла;
- отдельный плейлист для восстановленных треков;
- связь Original Track -> [[local-audio-file]] -> Uploaded TrackSource;
- replacement mapping;
- ручное подтверждение каждой операции;
- журналирование загрузок;
- отключаемость функции;
- обработка ошибок upload.

## Не входит

- гарантия стабильной загрузки;
- массовая автоматическая замена;
- удаление оригиналов без подтверждения;
- поддержка upload для других сервисов;
- публичная база файлов.

## Критерии готовности

- можно проверить, работает ли upload технически;
- можно загрузить один локальный файл, если API позволяет;
- создаётся связь между оригиналом и загруженной версией;
- каждая операция требует подтверждения;
- функция может быть отключена;
- ошибки upload видны пользователю.

## Риски

- upload может не работать через выбранную библиотеку;
- сервис может ограничивать загрузку;
- загруженный файл может не попасть туда, куда ожидается;
- могут появиться дубли;
- пользователь может случайно заменить не тот трек.

## Решение

Держать функцию экспериментальной.

Основной MVP не должен зависеть от upload. Если upload окажется невозможным, MusicArk всё равно остаётся полезным как архиватор, сканер, downloader и система контроля коллекции.

Короче: не строить дом на функции, которая может оказаться табличкой “доступ запрещён”.
