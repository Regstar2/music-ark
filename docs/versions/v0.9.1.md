# v0.9.1 — Main Screen UI Polish

Status: **Draft validation**

Python package: `0.9.1`  
Flutter app: `0.9.1+1`

## Goal

v0.9.1 unifies the desktop shell and Yandex Music workspace while preserving existing music-domain semantics and safety boundaries.

## Main changes

- one permanent global MusicArk sidebar instead of global + nested Yandex sidebars;
- top-level Yandex tabs for Tracks, Playlists and Albums;
- Albums represents the authenticated user's actual Yandex Music liked-album collection, not albums inferred from liked tracks;
- cache-first liked-album index plus lazy album-detail track caching using the existing provider collection storage;
- playlist and album detail screens with explicit back navigation;
- human-readable collection headers with count, relative update time and source;
- responsive search/sort/version-label toolbar;
- track sorting includes Yandex order, title, artist and unavailable-first;
- desktop table-like track rows with artwork, title/artist, album, label, duration and actions;
- compact track-row layout for narrower desktop windows;
- normal `available` provider value hidden from presentation;
- unavailable track playback disabled with explanatory tooltip;
- ORIGINAL/CENSORED inline chips, row editing and global manager preserved;
- shared presentation constants in `app_ui_tokens.dart`;
- lightweight theme-aware MusicArk vector mark;
- responsive application-wide Now Playing presentation;
- deterministic RU/EN localization in injected Flutter test mode without inheriting developer-machine settings.

## Liked albums contract

MusicArk reads the user's album likes through the pinned `yandex-music==3.0.0` client. The provider returns explicit album-like entries; MusicArk stores a sanitized index in its generic provider-collection cache. Opening one album loads its full ordered tracks lazily and caches that snapshot.

```text
Yandex liked albums
        ↓
cache index: liked_albums
        ↓
open album
        ↓
cache detail: album:<external_id>
```

This is read-only provider access. v0.9.1 does not like/unlike albums, mutate Yandex Music, or add a SQLite migration.

## Test-regression fixes

Windows validation of the earlier PR head exposed several independent test problems:

- injected full-app tests inherited the developer machine's persisted locale/theme settings, making Russian assertions nondeterministic;
- injected full-app tests could instantiate the real content-label process bridge and wait on a Python subprocess even though the main Yandex bridge was fake;
- old narrow-layout expectations still referenced the removed nested Yandex sidebar;
- several standalone Yandex tests lacked deterministic locale setup.

Injected app mode now uses isolated default settings and only enables the production content-label bridge when no fake main bridge is injected. Production startup continues to use the real persisted settings and feature bridges.

## Architecture

`app_shell.dart` remains the application lifetime/navigation boundary. The Yandex page stays in the shell `IndexedStack` and continues to use the logout revision as its explicit provider reset boundary. Theme/locale rebuilds do not deliberately replace the Yandex page with a new authentication/session implementation.

`ContentLabelBridgeClient` and `MetadataBridgeClient` stay explicit dependencies. Feature availability must never be inferred from the concrete runtime type of the main Yandex bridge because v0.9.x wraps that bridge to observe session state.

The old approximately 920 px forced Yandex workspace and horizontal scroll safeguard remains removed. Responsive behavior is handled inside the workspace with `LayoutBuilder`, flexible columns and compact/wide row variants.

## Unchanged boundaries

v0.9.1 intentionally does **not** change:

- Yandex authentication / credential storage;
- Matching identity semantics;
- Variant analyzer/user acceptance semantics;
- Coverage / Missing semantics;
- Download queue/acquisition semantics;
- Controlled Sync planning/apply semantics;
- Metadata Editor write semantics;
- ORIGINAL/CENSORED stored internal values;
- SQLite schema;
- provider mutation rules.

No Yandex Upload or reverse Sync is implemented.

## Safety

The existing safety contract remains authoritative:

```text
Scan     → read-only user audio
Matching → read-only user audio
Coverage → read-only user audio
Sync     → no user audio mutation
```

Metadata Editor remains the explicit ordinary path that may rewrite one existing indexed MP3 after a direct user action.
