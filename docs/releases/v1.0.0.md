## О релизе

v1.0.0 - первый стабильный публичный релиз MusicArk для Windows x64.
Версия фиксирует уже реализованный desktop MVP без добавления новых функций в
release freeze: локальная библиотека, интеграция с Яндекс Музыкой, Matching,
Coverage, Downloads, Metadata Editor, Controlled Sync, feedback и проверяемая
Windows-доставка.

MusicArk распространяется под MIT License для собственного кода проекта.
Сторонние компоненты сохраняют собственные лицензии, см.
`THIRD_PARTY_NOTICES.md` и `licenses/`.

MusicArk использует неофициальный API Яндекс Музыки через стороннюю библиотеку.
MusicArk не является официальным продуктом Яндекса и не аффилирован с Яндексом.

## Главное

- Первый стабильный Windows x64 release pipeline публикует portable ZIP,
  per-user installer, `SHA256SUMS.txt` и `update-manifest.json`.
- Portable и installed builds включают Flutter desktop app и frozen Python
  backend runtime; отдельный developer checkout или системный Python не нужен.
- Release package включает `LICENSE`, `THIRD_PARTY_NOTICES.md` и `licenses/`.
- Update flow проверяет manifest, размер и SHA-256 installer перед запуском и
  требует явного подтверждения пользователя.
- Signing status: `UNSIGNED`. Подходящий code-signing certificate с private key
  не был найден в проверенном окружении.

- Root `LICENSE` для собственного кода MusicArk: MIT, Copyright (c) 2026
  Regstar2.
- Third-party notices/license bundle для компонентов, реально попадающих в
  Windows artifacts.

### Изменено

- Windows packaging теперь требует и копирует `LICENSE`,
  `THIRD_PARTY_NOTICES.md` и `licenses/` в portable ZIP и installer directory.
- Release workflow использует подготовленный notes file вместо полностью
  автоматического `--generate-notes`.
- Release workflow запускает полный `scripts/ci.ps1` на exact tag перед сборкой
  финальных artifacts.
- README RU/EN и release checklist отражают выбранную MIT-лицензию, сторонние
  лицензии, unofficial Yandex API boundary и `UNSIGNED` signing status.

### Исправлено

- Release-facing документация теперь указывает MIT-лицензию собственного кода
  MusicArk и границу сторонних лицензий.
- Уточнено, что ZIP не называется signed artifact; Authenticode применим к PE
  executables и installer, а этот релиз публикуется как `UNSIGNED`.

### Безопасность

- Notices явно отделяют MusicArk MIT code от GPL/LGPL/MPL/Apache/BSD/MIT
  сторонних компонентов.
- Для FFmpeg, libmpv, `yandex-music`, `mutagen` и PyInstaller указаны лицензии
  и source/source-offer locations.
- Release notes не заявляют ручной owner GUI smoke опубликованных файлов как
  уже выполненный.

## Установка и обновление

### Новая установка

Скачайте один из файлов из GitHub Release:

- `MusicArk-Setup-1.0.0-x64.exe` - обычная per-user установка в
  `%LOCALAPPDATA%\Programs\Music Ark`;
- `MusicArk-1.0.0-win-x64.zip` - portable package; распакуйте ZIP и запустите
  `Music Ark.exe`.

Windows может показать предупреждение SmartScreen, потому что v1.0.0
публикуется без Authenticode подписи.

### Обновление

MusicArk хранит пользовательские данные отдельно от installation directory:
`%LOCALAPPDATA%\MusicArk`. Обычный uninstall не удаляет базу данных, кеши и
настройки пользователя.

Stable updater использует:

```text
https://github.com/Regstar2/music-ark/releases/latest/download/update-manifest.json
```

Update flow:

```text
check   -> прочитать и проверить manifest
prepare -> скачать installer и проверить размер + SHA-256
apply   -> после подтверждения повторно проверить и запустить installer
```

Обновление с более ранней публичной stable-версии не проверялось, потому что
v1.0.0 является первым публичным stable-релизом.

## Известные проблемы

- v1.0.0 artifacts публикуются как `UNSIGNED`; Windows SmartScreen может
  показать предупреждение при первом запуске installer или executable.
- Windows x64 - единственная release-платформа.
- Полная безопасная запись metadata реализована для MP3/ID3. Другие форматы
  остаются read-only в Metadata Editor, если для них нет отдельного safe writer.
- Provider-функции зависят от внешних API и доступности Яндекс Музыки.
- MusicArk не является двунаправленным filesystem mirror и не должен
  автоматически удалять, переименовывать или перезаписывать локальные треки.
