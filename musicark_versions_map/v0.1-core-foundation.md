# v0.1-core-foundation

## Цель

Создать базовое Python-ядро MusicArk без графического интерфейса.

На этом этапе приложение ещё не обязано работать с Яндекс Музыкой или локальной коллекцией. Главная задача — создать фундамент, который потом не придётся ломать.

## Главный результат версии

Рабочий каркас проекта с базовыми моделями, настройками, логированием, SQLite-подключением и CLI-командой проверки.

## Входит

- базовая структура проекта;
- модуль [[core]];
- подключение [[storage]];
- начальная SQLite-база;
- конфигурация приложения;
- логирование;
- базовые исключения;
- минимальный CLI;
- тестовая команда запуска ядра;
- подготовка структуры для будущих модулей.

## Не входит

- работа с Яндекс Музыкой;
- работа с локальной музыкальной папкой;
- скачивание треков;
- графический интерфейс;
- Android;
- torrent;
- синхронизация;
- редактирование метаданных.

## Критерии готовности

- проект запускается из CLI;
- создаётся или открывается SQLite-база;
- конфигурация читается и сохраняется;
- логирование работает;
- есть базовая структура папок;
- есть начальные тесты;
- нет зависимости от конкретного музыкального сервиса.

## Возможные CLI-команды

```text
musicark health-check
musicark db-init
musicark config-show
```

## Риски

- слишком рано начать писать Яндекс-специфику в [[core]];
- сделать структуру проекта слишком абстрактной и бесполезной;
- пропустить нормальное логирование.

## Решение

Сделать ядро минимальным, но чистым.

Не надо строить “идеальную архитектуру на века” до первого реального сценария. Так обычно рождаются проекты, которые выглядят как дипломная работа инопланетянина и не делают ничего полезного.
