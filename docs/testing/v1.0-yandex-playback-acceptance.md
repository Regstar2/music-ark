# Приёмка воспроизведения Яндекс Музыки v1.0

Этот чек-лист относится к GitHub Issue #41.

## Что изменено

- валидный disk playback cache проверяется до чтения сохранённого токена и до создания Yandex download provider;
- cache hit возвращает только локальный путь и не выполняет provider/network preparation;
- в рамках текущей сессии уже подготовленный существующий локальный путь повторно используется без второго bridge process;
- backend возвращает диагностические `timingsMs`: `cacheCheck`, `providerPrepare`, `total`; session bridge добавляет `bridgeRoundTrip`;
- защищённый provider media URL и token по-прежнему не передаются во Flutter;
- пока network preparation выполняется, строка трека остаётся интерактивно отрисованной, а кнопка Play показывает progress indicator.

## Ограничение архитектуры v1.0

Холодное первое воспроизведение трека, которого нет в playback cache, по-прежнему требует получить разрешённый provider download URL и полностью подготовить локальный файл до передачи пути встроенному player. В v1.0 намеренно не добавляется streaming protected URL во Flutter, массовый prefetch библиотеки или снижение качества по умолчанию.

Поэтому исправление удаляет повторяемый startup/cache overhead и делает источник задержки измеряемым, но не заявляет мгновенный cold play при необходимости сетевой загрузки полного файла.

## Автоматическая проверка

Regression tests должны подтвердить:

1. валидный disk cache работает даже без доступного сохранённого token и не создаёт `YandexMusicDownloadProvider`;
2. cold preparation помечается `cached=false` и содержит timing fields;
3. session bridge повторно возвращает существующий подготовленный путь без второго delegate/bridge call;
4. logout очищает session playback cache;
5. во время незавершённого prepare Play показывает progress indicator и остальная таблица остаётся отрисованной.

## Windows manual pass

Для одного некэшированного трека записать:

- время от нажатия Play до появления preparation indicator;
- `cacheCheck`;
- `providerPrepare`;
- `total` backend preparation;
- фактическое время до начала звука.

Затем воспроизвести этот же трек повторно в той же сессии и после перезапуска приложения.

Ожидается:

- повтор в той же сессии не запускает новый backend bridge call;
- повтор после перезапуска использует disk cache без Yandex network round-trip;
- UI не зависает во время cold preparation;
- повторный cached play существенно быстрее cold preparation.
