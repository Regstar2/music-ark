# v0.3.0 — Yandex Library / Playlists

## Goal

Promote MusicArk from a persistent Liked screen to a cache-first Yandex library containing Liked plus the user's playlists.

## Delivered design

- `YandexMusicProvider.list_playlist_metadata()` obtains the playlist index without loading every playlist body.
- `YandexMusicProvider.get_playlist(id)` loads one selected playlist and maps tracks into internal `ProviderTrack` models.
- `YandexLibraryService` orchestrates credentials, Liked cache, playlist cache, refresh, and logout.
- `PlaylistCacheRepository` stores playlist metadata and ordered membership in generic provider collection tables.
- bridge commands: `bootstrap`, `login`, `liked_refresh`, `playlists`, `playlist`, `playlist_refresh`, `library_refresh`, `logout`; old `refresh`/`cached` aliases remain.
- Flutter desktop uses a sidebar for Liked, playlist list, and individual playlist navigation.

## Cache semantics

Collection IDs:

```text
yandex_music / liked
yandex_music / playlist:<external_id>
```

Playlist item order is persisted through `position`. Added/removed/unchanged membership uses multiset semantics so duplicate track occurrences can be preserved. A reorder changes stored positions without falsely reporting membership changes.

A successful full playlist-index refresh deletes snapshots for playlists no longer returned by Yandex.

## Migration

Schema `1.2.0` adds collection metadata columns to `provider_collection_snapshots`. The migration is forward-only/idempotent and keeps existing v0.2 Liked snapshots/items. `.musicark/musicark.db` must not be deleted for the upgrade.

## Refresh strategy

Startup:

```text
credentials → cached Likes + cached playlist index → UI → network library refresh
```

`library_refresh` updates account, Likes, and playlist metadata only. Playlist bodies refresh lazily when opened or when the current playlist is explicitly refreshed. This avoids blocking the desktop UI on dozens or hundreds of per-playlist requests.

## Tests

Python coverage includes playlist metadata, ordered snapshots, membership changes, deletion, empty/duplicate IDs, offline cache behavior, v0.2 migration regression, bridge routing/errors, and provider lazy-fetch behavior.

Flutter widget coverage includes cached startup, sidebar, playlist list/open, tracks, search, sorting, refresh, logout, and network-error fallback.

## Manual validation still required

Mocked tests cannot prove the real account payload shape or Windows credential/Flutter runtime behavior. Before release, validate real playlists and offline restart on the user's Windows machine using `docs/testing/manual-test-plan.md`.

## Out of scope

No local scanner, matching, missing-tracks workflow, download, sync, player, playlist editing/upload, installer, or standalone packaging.
