# MusicArk v0.9.3 — Matching UI Redesign

## Цель

v0.9.3 перерабатывает desktop-представление `Matching`, чтобы результаты сопоставления Яндекс Музыки и локальной библиотеки читались как единое рабочее пространство сравнения, а не как набор многострочных `ListTile`.

Версия не меняет алгоритм Identity Matching, Variant-анализ, confidence, candidate generation, ручные решения или музыкальную SQLite-схему.

## Baseline

Версия строится поверх `main` после интеграции v0.9.2 Local Library UI & Multi-Root Selection. Общие Material 3 theme/localization правила и `AppUiTokens` v0.9.x используются повторно; отдельная дизайн-система и новые UI-зависимости не вводятся.

SQLite schema остаётся `1.8.4`.

## Matching workspace

Основное представление раздела становится сравнительной desktop-таблицей:

```text
Яндекс Музыка | Локальный файл | Уверенность | Статус
```

Верхняя часть страницы содержит:

- заголовок и поясняющий подзаголовок;
- пять отдельных summary metrics: Yandex tracks, Local tracks, Matched, Needs review и Not found;
- `Запустить сопоставление`;
- `Проверить версии`;
- read-only `Обновить` текущего состояния;
- отдельные информационные сообщения результатов Matching/Variant операций;
- статус доступности Variant-аудиоанализа и отдельный error state;
- counted filters для всех существующих Matching status;
- Search и Sort на существующем bridge query contract.

## Result rows

Каждая строка сохраняет одну Yandex identity и её текущую Local identity-кандидатуру/связь в одной горизонтальной структуре.

### Yandex column

Показывает:

- theme-aware placeholder вместо сетевой загрузки artwork;
- исполнителя и название;
- альбом, если он есть в текущем payload.

v0.9.3 не создаёт undocumented artwork URL и не выполняет отдельный provider request на каждую строку.

### Local column

Для найденного local track показываются исполнитель, название и путь. Для `unmatched` отображается явное состояние отсутствия локального файла.

### Confidence

Процент остаётся существующим Matching confidence. Большой круг с процентом удалён; вместо него используется компактное числовое значение и progress meter. Для `unmatched` успешный meter не рисуется.

UI не вводит собственные категории `high / medium / low` и не меняет thresholds Matching engine.

### Matching и Variant

Matching status и Variant status отображаются раздельно. Это сохраняет существующую доменную границу:

```text
Matching → какая это identity
Variant  → та ли это запись/версия
```

Поддерживаются существующие Matching states `matched / conflict / unmatched` и Variant states `same / altered / different_version / uncertain / not_checked`.

## Detail workflow

Клик по строке по-прежнему открывает существующий Matching detail workflow.

Сохраняются:

- Yandex/Local comparison;
- ORIGINAL/CENSORED labels;
- Variant verification;
- reviewed Variant acceptance/reset;
- conflict candidates;
- manual accept;
- manual reject.

v0.9.3 не переносит полный candidate review внутрь основной таблицы и не переписывает detail dialog как новый feature.

## Search, filters, sort and pagination

Фильтры продолжают использовать существующий backend contract:

```text
status = ''
status = 'matched'
status = 'conflict'
status = 'unmatched'
```

Search выполняется по submit, а не на каждый введённый символ. Sort продолжает использовать поддерживаемые bridge values `confidence / artist / title / status`.

`Load More` сохраняет текущие status/search/sort и append-ит следующую страницу. В footer отображается `Показано X из Y`.

## Responsive desktop behavior

Matching использует `LayoutBuilder` для верхних metric/search controls и horizontal scrolling для сравнительной таблицы, когда доступная desktop-ширина меньше минимальной ширины колонок.

Цель — сохранить структуру сравнения на 1600×950, 1366×768 и около 1000–1100 px без превращения версии в mobile redesign.

## Localization

Все новые строки основного Matching workspace добавлены в существующие RU/EN `gen_l10n` ARB resources.

Пути, filenames, provider/user metadata и backend error payload не переводятся.

Legacy detail strings, которые не менялись в v0.9.3, не являются причиной для unrelated полной локализации detail feature в этой версии.

## Safety / boundaries

v0.9.3 сохраняет существующие safety invariants:

```text
Matching / Variant analysis → не изменяют существующие пользовательские audio files
Manual identity decisions   → изменяют только MusicArk state
Content labels              → не изменяют Yandex Music или audio metadata
Variant acceptance          → не переписывает analyzer status в SAME
```

Metadata Editor остаётся explicit-write boundary для существующего локального файла.

Новая SQLite migration не добавляется.

## Tests

Flutter regression coverage обновляется для:

- пяти summary cards;
- counted status filters;
- Matching Run и Variant Run banners;
- Search / clear / Sort bridge contract;
- comparison table header и matched/conflict/unmatched rows;
- compact confidence presentation;
- independent Variant badge;
- existing detail/content-label workflow;
- manual candidate decision workflow;
- pagination и shown counter;
- empty state;
- narrow desktop rendering;
- dark theme;
- English localization нового workspace.

Existing Variant tests сохраняют проверки SAME / ALTERED / DIFFERENT_VERSION / NOT_CHECKED, acceptance/reset, unavailable FFmpeg и single-track recheck.

## Manual validation

Windows smoke должен проверить минимум:

1. Matching workspace на широкой desktop-ширине.
2. Filters, Search, Clear, Sort и Refresh.
3. Matched / Needs review / Not found rows.
4. SAME / ALTERED / DIFFERENT_VERSION / UNCERTAIN / NOT_CHECKED presentation.
5. Detail dialog, Content Labels, candidate accept/reject и Variant acceptance.
6. Pagination при выдаче больше page size.
7. Light / Dark / System.
8. Russian / English.
9. 1600×950, 1366×768 и окно около 1000–1100 px без RenderFlex overflow.

Результаты ручной проверки не считаются выполненными, пока не зафиксирован реальный Windows run на branch/PR head.

## Non-goals

В v0.9.3 не входят:

- новый Matching algorithm или confidence model;
- fingerprint changes;
- новый Variant analyzer;
- новые filesystem/audio mutations;
- Yandex Upload или reverse Sync;
- automatic replacement;
- новый artwork cache или per-row network artwork requests;
- redesign других feature pages;
- mobile UI;
- новая navigation/state-management система;
- installer/signing/auto-update;
- SQLite migration без фактической необходимости.

## Verification state

Source implementation и regression tests входят в ветку v0.9.3. Python/Flutter suites, Windows build и Windows visual smoke должны быть отмечены PASS только после фактического запуска на соответствующем commit/PR head.
