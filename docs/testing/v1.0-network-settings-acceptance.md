# Приёмка сетевых настроек v1.0

Этот чек-лист закрывает GitHub Issue #40 и описывает фактический сетевой контракт релиза v1.0.

## Поддерживаемые режимы

В релизном UI доступны только:

- `System` — HTTPX наследует поддерживаемые proxy environment variables процесса (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`);
- `Direct` — proxy environment отключён через `trust_env=False`;
- `Custom` — используется только явно настроенный HTTP/HTTPS/SOCKS5 proxy.

MusicArk v1.0 не устанавливает, не включает, не отключает и не удаляет Cloudflare WARP/VPN/tunnel software.

## Миграция

1. Создать/использовать старый `network_settings.json` с `networkMode=auto`.
2. Запустить приложение и открыть Settings.
3. Проверить, что выбран `System`.
4. Повторить для `networkMode=warp`.
5. Сохранить настройки и проверить, что schemaVersion стал `2`, а WARP-specific поля отсутствуют.

Ожидается: legacy `auto`/`warp` предсказуемо мигрируют в `System`; `Custom` никогда не превращается в `Direct` как fallback.

## Direct

1. Задать proxy environment variables для процесса.
2. Выбрать `Direct`.
3. Выполнить `Test connection`.

Ожидается: запрос не использует proxy environment.

## System

1. Выбрать `System`.
2. Выполнить `Test connection` с корректно настроенным runtime/environment proxy и без него.

Ожидается: запрос следует HTTPX `trust_env=True`. Этот контракт не заявляет отдельное чтение WinINET/Windows Registry сверх поддержки HTTPX.

## Custom proxy

1. Проверить HTTP proxy.
2. Проверить SOCKS5 proxy.
3. Остановить proxy и повторить запрос.

Ожидается: при недоступном Custom proxy возвращается ошибка; скрытого fallback в Direct нет.

## Секреты и UI

Проверить:

- пароль proxy отсутствует в `network_settings.json`;
- пароль не появляется в диагностических сообщениях;
- Settings не содержит WARP status/install/enable/disable controls;
- Settings не содержит карточку metadata source/provider keys;
- installer не содержит действий по установке/удалению WARP/VPN/tunnel software.

## Результат

- Автоматические regression tests: `NOT VERIFIED` до trusted CI финальной ветки.
- Windows manual network pass: `NOT VERIFIED` до повторной ручной приёмки.
