# v0.7-matching

## Цель

Связывать треки из Яндекс Музыки, локальные файлы и будущие источники через [[matching-engine]] и [[canonical-library]].

## Главный результат версии

Приложение умеет сопоставлять [[track-source]] и [[local-audio-file]], создавать [[track]] и строить начальную [[canonical-library]].

## Входит

- нормализация названий;
- нормализация исполнителей;
- сравнение по названию;
- сравнение по исполнителю;
- сравнение по альбому;
- сравнение по длительности;
- расчёт уверенности совпадения;
- создание [[track]];
- создание связей в [[canonical-library]];
- обработка точных совпадений;
- список спорных совпадений для [[conflict-resolver]];
- сохранение результатов в [[storage]].

## Не входит

- аудио-отпечатки, если это слишком тяжело для ранней версии;
- идеальное разрешение всех дублей;
- продвинутый UI конфликтов;
- поддержка других сервисов.

## Критерии готовности

- скачанные из Яндекс Музыки файлы связываются с исходными треками;
- локальные файлы можно сопоставить с треками из Яндекс Музыки;
- у совпадений есть уровень уверенности;
- спорные случаи не связываются автоматически;
- ручные решения можно сохранить;
- повторный запуск не ломает уже созданные связи.

## Возможные CLI-команды

```text
musicark match run
musicark match list-conflicts
musicark match accept --track ... --file ...
```

## Риски

- неправильное автоматическое сопоставление;
- грязные метаданные;
- дубли;
- разные версии одного трека;
- локальные файлы без тегов.

## Решение

Лучше недосопоставить, чем ошибочно связать.

Ошибочный матчинг — это когда программа уверенно говорит “я всё поняла”, а потом связывает live-версию с альбомной. Чисто человеческий уровень самоуверенности, но нам не надо.
