# Идея проекта

## Проблема

Личная музыкальная коллекция зависит от конкретного сервиса. Прежде чем строить архивирование и синхронизацию, MusicArk должен надёжно выполнять самый простой сценарий: подключиться к аккаунту и показать фактическую библиотеку пользователя.

## Целевая аудитория

Владелец проекта и пользователи, которым нужен локальный desktop-инструмент для дальнейшей работы со своей музыкальной коллекцией.

## Главный пользовательский сценарий

Пользователь запускает MusicArk, вводит токен Яндекс Музыки, проходит проверку аккаунта и видит список «Мне нравится».

## Почему проект имеет смысл

Этот сценарий является минимальной проверкой интеграции с музыкальным провайдером и основой для будущего локального архива. Если он не работает воспроизводимо, дальнейшие sync/download/metadata-функции не имеют надёжной основы.

## Что входит в MVP

- Windows Flutter UI;
- ввод токена;
- проверка аккаунта;
- получение «Мне нравится»;
- отображение треков;
- понятные ошибки запуска, Python и авторизации.

## Что не входит в MVP

- сохранение токена;
- OAuth Device Flow;
- скачивание;
- локальная библиотека;
- сопоставление треков;
- синхронизация;
- редактирование метаданных;
- installer и bundled Python.

## Риски

- используется неофициальная Python-библиотека `yandex-music`;
- внешний API может изменить поведение;
- текущая release-сборка зависит от установленного Python и checkout репозитория.

## Критерий успеха первой версии

На Windows после выполнения команд из README пользователь запускает приложение, вводит действующий токен и видит свой актуальный список «Мне нравится».
