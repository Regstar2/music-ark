# v0.8-sync-planner

## Цель

Научиться строить план синхронизации без немедленного выполнения опасных действий.

## Главный результат версии

MusicArk умеет сравнивать состояние Яндекс Музыки, локального архива и предыдущих снимков, после чего формирует понятный SyncPlan.

## Входит

- модель SyncPlan;
- модель SyncOperation;
- сравнение снимков коллекции;
- обнаружение remote_only;
- обнаружение local_only;
- обнаружение missing_local_copy;
- обнаружение remote_unavailable;
- обнаружение metadata_changed;
- обнаружение needs_review;
- генерация операций;
- dry run;
- текстовый отчёт;
- создание [[download-task]] из плана;
- запись плана в [[storage]].

## Не входит

- автоматическое выполнение всех операций;
- upload в Яндекс Музыку;
- массовое удаление;
- продвинутый GUI;
- Android.

## Критерии готовности

- можно построить план без выполнения;
- пользователь может увидеть список будущих операций;
- опасные операции помечаются отдельно;
- download-операции превращаются в [[download-task]];
- план можно сохранить;
- план можно отменить;
- план можно повторно открыть.

## Возможные CLI-команды

```text
musicark sync plan
musicark sync plan --dry-run
musicark sync plan-show --id ...
```

## Примеры операций

```text
DOWNLOAD_TRACK
MARK_REMOTE_UNAVAILABLE
LINK_LOCAL_FILE
NEEDS_REVIEW
UPDATE_METADATA
UPLOAD_CANDIDATE
```

## Риски

- случайное выполнение операций на этапе планирования;
- слишком сложные планы;
- неочевидные причины операций;
- отсутствие истории.

## Решение

[[sync-planner]] только планирует.

Выполнение — задача [[sync-executor]]. Да, разделение звучит скучно. Зато скучная архитектура обычно не удаляет коллекцию в три часа ночи.
