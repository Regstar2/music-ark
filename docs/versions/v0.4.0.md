# MusicArk v0.4.0 — Local Library

## Goal

Add a persistent, read-only local music library alongside the existing Yandex Music library and create the structured local metadata foundation required by v0.5 Matching.

## User flow

```text
MusicArk
  ↓
Локальная библиотека
  ↓
Добавить папку
  ↓
Windows folder picker
  ↓
recursive scan
  ↓
metadata extraction
  ↓
shared SQLite
  ↓
browse / search / sort
```

## Implementation

### Application boundary

```text
Flutter
  ↓
musicark.mvp_bridge
  ↓
LocalLibraryService
  ↓
LocalLibraryScanner
  ↓
LocalMetadataReader
  ↓
LocalLibraryStorageRepository
  ↓
SQLite
```

Local filesystem scanning is not modeled as a Yandex provider.

### Roots

`local_library_roots` persists source path, normalized path, enabled flag, creation time, and last scan time. Duplicate and parent/child overlapping roots are rejected.

### Incremental scan

For each supported file:

```text
normalized path exists in DB?
        ↓
size + mtime_ns unchanged?
   yes → keep metadata / unchanged
   no  → read metadata / update
missing after complete traversal → delete index row
```

The supported v0.4 pipeline does not recalculate SHA-256 for every unchanged file. Hash remains a nullable/legacy-compatible concept for later identity/dedup needs.

A directory traversal error suppresses missing-file deletion for that scan, preventing a temporarily inaccessible subtree from being interpreted as mass deletion.

### Metadata

Read-only `mutagen` extraction includes title, artists, album, album artist, track/disc number, year, genre, duration, codec/extension, bitrate, and sample rate where available. Missing title falls back to filename stem. Missing artist is represented structurally and displayed as `Unknown Artist`.

### Storage

Migration `1.3.0` extends the existing `local_audio_files` table and creates `local_library_roots`. Scan upserts and reconciliation run transactionally. Search and sort are SQL-backed, and track listing exposes `limit`/`offset`.

Existing Yandex `provider_collection_snapshots` and `provider_collection_items` are preserved.

### UI

- top-level navigation between Yandex Music and Local Library;
- native folder picker through `file_selector`;
- roots list with scan-one/remove actions;
- scan-all action and final added/updated/removed/unchanged/errors summary;
- local track list;
- search by title/artist/album/filename;
- sorting by artist/title/album/duration/path;
- track detail dialog with metadata and file path;
- explicit index-only removal warning.

## Safety

v0.4 is read-only toward local audio files. The supported flow does not rename, move, delete, edit tags, transcode, or alter artwork. Removing a folder from MusicArk only removes index records.

No local-file metadata is sent to external services by the Local Library flow.

## Tests

Python coverage includes empty/nested scans, supported/unsupported files, missing tags, corrupted files, Unicode paths, duplicate/overlapping roots, incremental new/unchanged/modified/deleted behavior, idempotency, search/pagination, root removal safety, and v0.3 → v0.4 migration preservation.

Flutter widget coverage includes Local Library navigation, empty state, mocked folder selection, roots, scan result, tracks, search, sorting, and index-only root removal confirmation. Existing v0.3 Yandex widget tests remain in place for regression coverage.

## Manual validation still required

The repository/CI environment cannot prove native Windows folder picker behavior or scan the user's actual local collection. Before accepting v0.4, run the documented `C:\MusicArk-Test` sequence on the user's Windows machine and re-check Yandex session/Likes/playlists afterward.

## Out of scope

Matching, missing-track detection, download, sync, playback, metadata editing, file moving/renaming/deletion, transcoding, duplicate cleanup, album-art downloading, standalone packaging, and installer work remain outside v0.4.
