# MusicArk v0.9.5 — Downloads UI, Safe Deletion & Bulk Actions

## Цель

v0.9.5 перерабатывает desktop-раздел `Загрузки` в рабочее пространство управления очередью и добавляет безопасные массовые действия.

Версия строится поверх полностью интегрированной v0.9.4 и не меняет Matching, Variant Detection, Coverage calculation, Controlled Sync, Metadata Editor или музыкальную SQLite-схему.

SQLite schema остаётся `1.8.4`.

## Downloads workspace

Экран использует:

- компактные вкладки `Загрузки` / `Нужные` со счётчиками;
- отдельные summary-метрики `В очереди`, `Загружается`, `Завершено`, `Ошибки`;
- компактную карточку папки загрузок;
- единый toolbar с поиском, status filters и основными queue actions;
- компактные строки треков вместо больших карточек;
- lazy rendering через `CustomScrollView` / `SliverList`;
- локальный artwork placeholder без дополнительных сетевых запросов;
- реальный progress и indeterminate progress при неизвестном total;
- человекочитаемые сообщения ошибок и отдельные технические сведения.

Поиск выполняется по уже загруженному operational task list и не делает сетевых запросов.

## Safe task removal

Для `failed` и `needs_review` доступно отдельное действие `Удалить`.

Удаление download task означает только удаление записи задачи из download history/queue storage.

Операция специально не удаляет:

- final audio file;
- запись Local Library;
- Matching result;
- Coverage state;
- provider cache;
- пользовательскую отметку Wanted;
- данные Яндекс Музыки;
- audit history.

Перед удалением требуется явное подтверждение. Для ожидаемого sibling `.part` разрешена best-effort cleanup с проверкой безопасного пути. Final file этой операцией не удаляется даже для `needs_review`.

`queued` и `running` нельзя удалить напрямую: активную задачу нужно отменять через существующий cancellation workflow.

Каждое успешное удаление оставляет audit event `download_task_removed`.

## Bulk actions

Строки `Загрузок` и `Нужных` поддерживают selection.

`Выбрать все видимые` выбирает только текущий набор после активного filter/search. При переключении вкладки selection очищается.

Для Downloads доступны:

- bulk retry для `failed` / `needs_review`;
- bulk cancel для `queued` / `running`;
- bulk remove для `failed` / `needs_review`.

Для Wanted доступны:

- индивидуальный Download;
- Download all;
- Download selected.

Batch bridge передаёт список ID одним Python process через временный JSON payload. Результат batch operation содержит `requested / processed / succeeded / failed / skipped / items / errors`, поэтому частичный успех не маскируется.

## Queue isolation

Критический инвариант версии:

```text
Retry selected        != run the entire old queue
Download selected     != run the entire old queue
Download all Wanted   != run pre-existing queued tasks
```

Bulk retry сначала переводит только выбранные retryable tasks в `queued`, затем запускает только task IDs из результата этого действия.

Download selected enqueue'ит только выбранные external IDs и запускает только полученные task IDs.

Явная кнопка `Продолжить очередь` сохраняет существующий последовательный workflow и прекращает drain после текущего трека, если пользователь покинул страницу.

## Backend boundary

Flutter не получает прямой доступ к SQLite.

Поток batch operations:

```text
DownloadPage
  -> DownloadBridgeClient
  -> musicark.download.actions_bridge
  -> DownloadService / persisted download state
```

Batch bridge дополнительно проверяет, что пользовательские операции не применяются к internal/legacy download tasks.

## Localization

Новые пользовательские строки Downloads находятся в существующих RU/EN ARB resources.

Backend codes, task IDs, provider IDs и raw technical messages не переводятся и показываются только в technical details.

## Non-goals

В v0.9.5 не входят:

- Yandex Upload;
- удаление музыки из Яндекс Музыки;
- удаление local audio files через Downloads;
- новый download provider;
- background download daemon;
- изменение Matching/Variant/Coverage algorithms;
- изменение Controlled Sync;
- новый state-management framework;
- новый artwork network loader;
- SQLite migration.

## Manual validation

Windows smoke должен проверить layout, confirmation dialogs, bulk operations, Light/Dark/System, RU/EN и отсутствие overflow на обычной desktop-ширине.

Ручная проверка не считается выполненной, пока приложение действительно не запущено на Windows из head этой ветки/PR.
