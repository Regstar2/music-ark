# v0.9-desktop-ui

## Цель

Сделать первую Windows-версию с графическим интерфейсом.

## Главный результат версии

Появляется desktop UI, который позволяет пользоваться уже созданными функциями без CLI.

## Входит

- Flutter-проект;
- [[platform-bridge]] для связи с Python Core;
- Dashboard;
- экран коллекции;
- экран локальной библиотеки;
- экран провайдеров;
- [[download-queue-ui]];
- экран плана синхронизации;
- базовый экран конфликтов;
- экран логов;
- базовые настройки;
- показ ошибок;
- запуск сканов из UI.

## Не входит

- Android;
- полноценный редактор метаданных;
- upload;
- torrent;
- поддержка других сервисов;
- музыкальный плеер.

## Критерии готовности

- приложение запускается на Windows;
- UI подключается к Python Core;
- можно запустить скан Яндекс Музыки;
- можно запустить скан локальной библиотеки;
- можно увидеть коллекцию;
- можно увидеть план синхронизации;
- можно увидеть очередь загрузок;
- можно увидеть логи;
- ошибки не теряются.

## Техническая реализация (первая итерация)

- Flutter desktop проект расположен в `ui/musicark_ui`;
- UI вызывает только Python `platform-bridge` (`musicark.platform_bridge`);
- bridge отдаёт snapshot для экранов: Dashboard, Collection, Local Library, Providers, Download Queue, Sync Plan, Conflict View, Logs, Settings;
- bridge запускает действия: `scan_yandex`, `scan_local`, `match_run`, `sync_plan`;
- синхронизация остаётся dry-run через [[sync-planner]], без переноса бизнес-логики в Dart.

## Риски

- UI начнёт содержать бизнес-логику;
- bridge станет помойкой из команд;
- большие таблицы будут тормозить;
- ошибки Python будут плохо отображаться.

## Решение

UI только показывает и отправляет команды.

Вся логика остаётся в [[core]]. Кнопка “скачать” не должна знать, как именно скачивать. Кнопка вообще не должна знать слишком много, иначе она станет менеджером проекта.
