# MusicArk AI text guardrails

AI-generated project text must be evidence-based.

- Do not claim tests/builds/manual acceptance passed unless the exact check was executed and evidence is available.
- Use `NOT VERIFIED` for unavailable checks.
- Do not invent user counts, performance claims, compatibility, security guarantees, API behavior or release dates.
- Distinguish implemented, experimental, planned and blocked behavior.
- Release notes are derived from actual merged changes and current verification, not from roadmap intent.
- Do not expose secrets, account identifiers, private library contents, local paths or sanitized-away diagnostic fields.
- Keep RU/EN documentation factually aligned.
- Prefer concrete commands, files, states and limitations over promotional wording.
