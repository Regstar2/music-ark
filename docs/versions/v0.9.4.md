# MusicArk v0.9.4 — Coverage / Missing UI Polish

## Цель

v0.9.4 перерабатывает desktop-представление `Coverage / Недостающие`, чтобы экран показывал состояние локального покрытия как рабочий список треков, а не как техническую строку статистики и набор разрозненных фильтров.

Версия не меняет Coverage calculation, Identity Matching, Variant analysis, Download semantics, Controlled Sync или музыкальную SQLite-схему.

## Baseline

Версия строится поверх `main` после интеграции v0.9.3 Matching UI Redesign. Используются существующие Material 3 theme/localization правила MusicArk; новые UI-зависимости и отдельная дизайн-система не вводятся.

SQLite schema остаётся `1.8.4`.

## Coverage workspace

Верхняя часть страницы содержит:

- локализованный заголовок и пользовательский подзаголовок;
- компактную карточку локального покрытия с процентом и progress indicator;
- отдельные показатели `Всего`, `Найдено`, `Отсутствует`, `Не анализировано`;
- сворачиваемые детали Matching/Variant анализа;
- counted status tabs для `missing / needs_review / not_analyzed / covered`;
- один responsive toolbar для Collection, Search, Decision, Sort и Variant filter.

Полная Variant-статистика больше не занимает постоянное место в основном рабочем пространстве.

## Track rows

Coverage rows используют существующий provider payload и показывают:

- artwork из `provider['artwork_url']`;
- локальный theme-aware placeholder при отсутствии URL, загрузке или network error;
- название трека как основной текст;
- исполнителя и альбом как secondary metadata;
- membership в `Мне нравится` и плейлистах как компактные badges;
- отдельный Coverage status badge;
- Variant badge только для covered identity.

Artwork URL не конструируется во Flutter. UI использует уже сохранённое поле `ProviderTrack.artwork_url` и не получает provider token/cookies/Authorization headers.

## Missing actions

Для `missing` сохраняется существующая семантика:

```text
Скачать      → существующий direct Download workflow
Нужен        → userAction = wanted
Игнорировать → userAction = ignored
Сбросить     → userAction = unreviewed
```

`Скачать` не изменяет `userAction`. Bulk selection по-прежнему выполняет только triage actions и не получает bulk-download.

## Selection and pagination

Отдельная строка с кнопкой `Выбрать всё` заменена master-checkbox в header списка.

Select All продолжает выбирать все результаты текущего Missing filter через существующий paged bridge workflow, а не только текущие 100 отображаемых элементов. Partial selection использует indeterminate state.

Pagination скрывается, если `total <= pageSize`, и сохраняет существующий backend paging contract для больших результатов.

## Localization

Все пользовательские статические строки затронутого Coverage workspace и details dialog находятся в существующих RU/EN `gen_l10n` ARB resources.

Provider data, artist/title/album values, IDs, backend codes и technical reason payload не переводятся.

## Responsive desktop behavior

Coverage сохраняет один desktop layout и reflow через `LayoutBuilder` / `Wrap`:

- summary metrics переносятся по доступной ширине;
- toolbar controls переносятся без RenderFlex overflow;
- track actions уходят под identity metadata на compact desktop width;
- artwork не вытесняет primary Download action;
- 315 px используется только как regression width, а не как отдельный mobile redesign.

## Safety / boundaries

v0.9.4 сохраняет существующие инварианты:

```text
Coverage                → derived/read-only view over provider/matching/local state
Matching / Variant      → не изменяют существующие пользовательские audio files
Download                → отдельный explicit acquisition workflow
Wanted / Ignored        → MusicArk-local triage state
Controlled Sync         → существующий enqueue-only controlled workflow
Metadata Editor         → explicit write boundary для существующего local file
```

Новая SQLite migration не добавляется.

## Tests

Flutter regression coverage обновляется для:

- компактной summary и раскрытия analysis details;
- counted status tabs;
- Collection/Search/Sort/Decision/Variant filters;
- master Select All и partial indeterminate state;
- существующих Download/Wanted/Ignored invariants;
- artwork fallback без реальной сети;
- localized details dialog;
- скрытой pagination для одной страницы и paging для большой выдачи;
- English localization;
- 1024 px, 760 px и 315 px responsive regressions.

## Manual validation

Windows smoke должен проверить минимум:

1. Coverage summary и analysis details.
2. Все четыре status tabs.
3. Collection, Search, Decision, Sort и Variant filter.
4. Artwork и fallback при недоступной картинке.
5. Download, Wanted, Ignore и Reset.
6. Single selection, Select All и bulk triage.
7. Pagination на выдаче больше 100 результатов.
8. Details dialog и переход в Matching.
9. Light / Dark / System.
10. Russian / English.
11. Широкое и compact desktop window без overflow.

Результаты ручной проверки не считаются выполненными, пока не зафиксирован реальный Windows run на branch/PR head.

## Non-goals

В v0.9.4 не входят:

- новый Coverage algorithm;
- изменения Matching/Variant thresholds;
- новый Download provider или bulk-download;
- Yandex Upload или reverse Sync;
- новый artwork cache/dependency;
- новые filesystem/audio mutations;
- redesign других feature pages;
- mobile navigation;
- новая state-management/navigation архитектура;
- SQLite migration.

## Verification state

Source implementation и regression tests входят в ветку v0.9.4. Python/Flutter suites, Windows build и Windows visual smoke отмечаются PASS только после фактического запуска на соответствующем commit/PR head.
