# v1.0.0 — First Public Release

## Goal

Freeze the tested MusicArk feature set and prepare the first public Windows release without adding new product scope.

v1.0.0 is the release boundary for the functionality accumulated through v0.15 plus the Windows acceptance fixes merged after that baseline.

## Release contents

The Windows release pipeline produces:

- `MusicArk-1.0.0-win-x64.zip` — portable package;
- `MusicArk-Setup-1.0.0-x64.exe` — per-user Inno Setup installer;
- `SHA256SUMS.txt` — SHA-256 checksums from the final artifacts;
- `update-manifest.json` — stable update metadata containing the exact installer URL, byte size and SHA-256.

Installed and portable builds include the Flutter desktop application and the frozen MusicArk backend runtime. A separate system Python installation or developer checkout is not required.

## Stable update channel

The default stable channel points to:

```text
https://github.com/Regstar2/music-ark/releases/latest/download/update-manifest.json
```

`MUSICARK_UPDATE_MANIFEST_URL` remains available as a deployment/test override.

The update boundary is unchanged:

```text
check   -> read and validate manifest only
prepare -> download and verify exact size + SHA-256
apply   -> require explicit confirmation, re-verify, then launch installer
```

A missing release, unavailable endpoint, malformed manifest, untrusted redirect, size mismatch or hash mismatch fails closed and must not prevent ordinary MusicArk use.

## Windows acceptance fixes included in v1.0

The final acceptance rounds merged the following release-blocking fixes:

- Matching persists bounded batches on the active run connection instead of opening a competing SQLite writer in the hot loop;
- Matching and large Coverage/Missing actions expose progress and keep bounded read/write chunks so large libraries do not rely on one oversized operation;
- Downloads refreshes Wanted/queue state on initial load and reactivation;
- Download All enqueues first, refreshes the visible queue immediately and drains work through a bounded asynchronous sequential worker;
- the long-running Yandex download path reuses one worker/service/client session, applies bounded retry for transient provider/network failures, stops on authentication/systemic circuit-breaker conditions, and classifies unsupported UGC UUID tracks separately;
- portable ZIP creation uses `System.IO.Compression.ZipFile` with bounded retries, removes partial archives and requires non-empty output plus checksums;
- Yandex playback checks disk/session cache before expensive provider setup, reducing repeat-play preparation latency;
- Cloudflare WARP ownership/control was removed from the application runtime and Settings; network modes are System / Direct / Custom proxy;
- unavailable source cards were removed from the track-details UI while packaged supported provider modules remain explicit release dependencies.

These changes do not redefine Matching/Variant/Coverage truth, silently mutate local audio, or introduce automatic Yandex collection mutation.

## Version contract

`VERSION` is canonical and must equal `1.0.0` in:

- `pyproject.toml`;
- `src/musicark/__init__.py`;
- `ui/musicark_ui/pubspec.yaml` (semantic version before build metadata);
- `ui/musicark_ui/lib/app_info.dart`.

SQLite remains `1.9.0`.

## Verification and publication boundary

Source-level completion is not publication evidence. The release is publishable only after:

1. trusted CI is green on the final v1.0.0 source;
2. the repository is public and public feedback/update URLs are reachable;
3. the owner selects and adds the intended project `LICENSE` and verifies required third-party notices/licenses;
4. final Windows artifacts are built from the exact accepted source/tag;
5. installer signing state is stated factually as signed or `UNSIGNED`;
6. `v1.0.0` is created without later moving the tag;
7. the GitHub Release contains only the final `dist/` artifacts and post-publication links are smoke-tested.

No final artifact hash, signature status, public visibility, GitHub Release or post-release smoke result is claimed by this source document before that evidence exists.
