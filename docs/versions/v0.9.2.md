# MusicArk v0.9.2 — Local Library UI & Multi-Root Selection

## Цель

v0.9.2 перерабатывает desktop-представление `Local Library` и добавляет полноценный фильтр по произвольному набору library roots без изменения музыкальной семантики MusicArk.

Пользователь может просматривать:

- все добавленные папки;
- одну конкретную папку;
- произвольный subset из нескольких папок;
- пустой набор папок как отдельное состояние с нулевой выдачей.

## Baseline

Версия строится поверх `main` после v0.9.1 Main Screen UI Polish. Общие Material 3 theme/localization правила и `AppUiTokens` v0.9.1 используются повторно; отдельная дизайн-система не вводится.

SQLite schema остаётся `1.8.4`.

## Multi-root query contract

Local Library сохраняет существующую single-root модель для операций, где один root является частью команды, например scan/remove. Для просмотра треков добавляется отдельный `rootIds` query contract.

Семантика:

```text
rootIds = null     → фильтр по roots не задан, показать все roots
rootIds = []       → не выбран ни один root, count = 0, items = []
rootIds = [1]      → только root 1
rootIds = [1,3,7]  → union roots 1, 3 и 7
```

Цепочка запроса:

```text
LocalLibraryPage selection
        ↓
MusicArkBridgeClient.localTracks(rootIds)
        ↓
mvp_bridge.py --root-ids JSON
        ↓
LocalLibraryService.tracks(root_ids)
        ↓
LocalLibraryStorageRepository.list_tracks(root_ids)
        ↓
SQLite WHERE library_root_id IN (?, ...)
```

`--root-id` сохраняется для совместимости и для single-root операций. Одновременная передача `rootId` и `rootIds` считается invalid request.

Root IDs передаются как typed JSON array, валидируются на process boundary, deduplicate-ятся и не строятся из пользовательских путей.

## Query correctness

Root predicate применяется в SQLite до:

- `COUNT`;
- search predicate;
- `ORDER BY`;
- `LIMIT`;
- `OFFSET`.

Поэтому `_total`, Search, Sort и Load More относятся к одному и тому же выбранному subset, а не к первым загруженным Flutter rows.

## Selection lifecycle

UI хранит selection по `root.id`, а не по path.

При первом открытии выбраны все существующие roots.

Reconciliation при изменении root set:

- если до добавления были выбраны все roots, новый root также становится выбранным;
- если пользователь работал с subset, новый root автоматически не добавляется;
- удалённый root всегда удаляется из selection;
- пустой selection остаётся отдельным пользовательским состоянием и не превращается в «Все».

## Local Library UI

Страница получила desktop-композицию в стиле v0.9.1:

- header с количеством треков и состоянием выбора roots;
- действия `Добавить папку` / `Сканировать` справа или с переносом на узком desktop layout;
- единый toolbar Search / folder multi-select / Sort;
- persistent multi-select dialog с master checkbox `Все папки` и tri-state presentation для subset;
- отдельный компактный блок управления library roots;
- сокращённый scan status для обычного успешного результата и явное error state при ошибках;
- table-like track rows на широкой области и compact rows на более узкой;
- artwork, title/artist, album, year, format, ORIGINAL/CENSORED, duration и actions;
- primary actions `Play` / `Metadata Editor`, secondary details/reveal через overflow;
- отдельные empty states для отсутствующих roots, пустого selection и отсутствия search results.

Folder management и folder view filter остаются разными сущностями: выбор root в фильтре ничего не добавляет, не удаляет и не сканирует.

## Localization

Все новые пользовательские строки Local Library добавлены в существующие `gen_l10n` RU/EN ARB resources.

Не переводятся:

- пути и filenames;
- provider/user metadata;
- codec names;
- IDs и backend codes.

## Safety / boundaries

v0.9.2 не меняет существующие safety invariants:

```text
Scan      → read-only user audio
Matching  → read-only user audio
Coverage  → read-only user audio
Sync      → no local-only audio deletion
```

Multi-root selection является только query/view state.

Metadata Editor остаётся отдельным explicit-write workflow для одного существующего пользовательского файла.

ORIGINAL/CENSORED labels остаются MusicArk-local presentation state и не изменяют Yandex Music или аудиотеги.

## Non-goals

В v0.9.2 не входят:

- Yandex Upload;
- reverse Sync;
- новый Matching или Variant engine;
- automatic DIFFERENT_VERSION replacement;
- bulk metadata editing;
- новый playback engine;
- mobile UI;
- новый router/state-management framework;
- telemetry/cloud account;
- installer/auto-update;
- unrelated redesign остальных страниц;
- SQLite migration без фактической необходимости.
