# MusicArk v0.8.1 — Rich Yandex Download Metadata / Provenance

## Product goal

v0.8.1 hardens the existing v0.7 production Yandex download path so MusicArk-created MP3 files retain useful standard metadata and trusted provider provenance across rescans and fresh Local Library indexing.

## Download materialization

The intended acquisition path remains the existing `DownloadService` flow. For a newly downloaded MP3, available Yandex metadata is normalized and written before final publication of the file.

The safety sequence is:

```text
authorized provider transfer
→ .part file
→ audio validation
→ metadata/provenance enrichment
→ final validation
→ atomic finalization
→ Local Library index/link/Coverage refresh
```

Artwork enrichment is best-effort. A failure to obtain artwork must not weaken the critical validation/finalization boundary.

## Provenance

MusicArk-created Yandex downloads may contain trusted MusicArk/Yandex provenance frames. These are distinct from fuzzy metadata similarity and can later support exact provider-identity recovery when validated.

The provenance contract must not expose credentials, Authorization headers, cookies or protected/signed media URLs.

## Filename collision safety

An existing user file is not overwritten merely because its filename matches a proposed MusicArk download destination. Collision handling must choose a safe result rather than replacing unrelated user content.

## Downloads UX follow-up

v0.8.1 also includes the Downloads → Wanted flow and select-all support for filtered Missing tracks while preserving queue isolation. Controlled Sync still delegates acquisition to `DownloadService.enqueue()` and does not drain unrelated queued tasks.

## Schema

```text
1.8.0 → 1.8.1  rich Yandex download metadata/provenance support
```

The migration is forward-only and must preserve existing application data.

## Non-goals

- no editor for arbitrary existing user files in v0.8.1;
- no automatic replacement of Different Version;
- no new Sync architecture;
- no Yandex library mutation;
- no destructive migration or database reset.

The explicit editor for existing local files belongs to v0.8.2.
