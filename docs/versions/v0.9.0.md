# MusicArk v0.9.0 — UI, Account & Settings

## Цель

v0.9.0 превращает функциональный baseline v0.8.2 в более цельное desktop-приложение без добавления новых музыкальных возможностей.

Основные блоки:

```text
Global Account/Profile UI
Settings
Theme system
Localization RU / EN
Help / About
UI shell cleanup
```

Yandex Upload не входит в эту версию.

## Baseline

v0.8.2 принят в `main` через PR #14. Ветка v0.9.0 строится от merge commit `8d6520085567d0998801a0cbbaf5551782f6394b` и должна открывать PR в `main`.

## Account UX

Global account control находится в нижней utility-зоне левой панели под `Настройки`.

Состояния:

```text
нет stored session → user icon + Войти
stored session      → initials/icon + displayName
```

`Войти` открывает существующий раздел Яндекс Музыки и не создаёт второй login flow. Login/logout продолжают выполняться через `MusicArkBridgeClient` и backend `YandexLibraryService`.

`SessionAwareMusicArkBridge` обновляет `AccountSessionController` из тех же session payload, которые получает Yandex UI. Поэтому login/logout и refresh не имеют отдельной глобальной credential logic.

## Avatar

Pinned dependency: `yandex-music==3.0.0`.

Используемый `Account` DTO (`client.me.account`) не документирует подтверждённый публичный avatar URI. v0.9.0 поэтому не придумывает поле или URL-шаблон и не передаёт Yandex token/cookies во Flutter.

Fallback:

```text
displayName = Regstar2     → R
displayName = Иван Петров  → ИП
нет displayName            → generic user icon
```

## Theme model

`AppSettingsController` хранит:

```text
themeMode = system | light | dark
```

`MaterialApp` использует централизованные `AppTheme.light` / `AppTheme.dark`, Material 3 и `ColorScheme`. Theme меняется без restart. `system` делегирует выбор `ThemeMode.system` платформе.

## Localization model

Поддерживаются `ru` и `en` через стандартные Flutter `flutter_localizations` + `gen_l10n` + ARB resources.

```text
localeMode = system | ru | en
```

Для `system`:

```text
ru → ru
en → en
другое → ru
```

Новые shell/account/settings/help/about surfaces используют generated localization resources. Исторические feature widgets с ранее встроенными русскими literals должны переноситься в ARB без изменения backend codes и provider data; до завершения этого переноса English mode нельзя считать полной локализацией всего активного UI.

## Settings persistence

Preferences хранятся отдельно от музыкальной SQLite БД в минимальном typed JSON store:

```text
~/.musicark/ui_preferences.json
```

Содержимое ограничено `schemaVersion`, `themeMode`, `localeMode`. SQLite schema остаётся `1.8.4`.

## Help

Help работает offline и объясняет:

- Яндекс Музыку;
- Local Library;
- Matching;
- Missing;
- Downloads;
- Sync;
- Metadata Editor.

Критичные различия:

- Matching != Variant;
- Missing != Different Version;
- Sync не удаляет local-only файлы;
- Apply Metadata != Apply + Bind.

## About

About показывает:

- MusicArk `0.9.0`;
- backend `0.9.0`;
- schema `1.8.4`;
- OS;
- theme/locale;
- GitHub repository.

`Скопировать информацию для диагностики` не включает token, cookies, protected URLs, список файлов или содержимое пользовательской библиотеки. Open-source dependency licenses открываются через стандартный Flutter license UI. Лицензия самого MusicArk не выдумывается.

## Application-shell lifecycle

Yandex page остаётся внутри `IndexedStack`. Theme/locale rebuild `MaterialApp` не меняет ключ Yandex page. После logout используется отдельный `logoutRevision`, чтобы сбросить provider UI в logged-out state без restart.

Settings, Help и About находятся внутри того же shell; `MusicArkNowPlayingBar` остаётся ниже `IndexedStack` и не заменяется новым playback engine.

Yandex workspace сохраняет safeguard минимальной ширины около `920 px` с horizontal scrolling.

## Сохранённые v0.8.2 границы

Не меняются:

```text
Scan     → read-only user audio
Matching → read-only user audio
Coverage → read-only user audio
Sync     → no user audio mutation
```

Metadata Editor остаётся обычным explicit-write workflow для существующего user audio.

Не изменяются семантики Matching, Variant, Coverage, Download, Controlled Sync и Metadata Editor.

## Tests

Добавлены Flutter tests для:

- typed settings persistence;
- account initials/cache-preservation/logout revision;
- logged-out / logged-in account control;
- generic avatar fallback;
- long displayName overflow regression;
- system locale fallback;
- runtime theme/locale switch;
- Help/About внутри shell с Now Playing.

Полный Python suite, `flutter analyze`, targeted Flutter tests, полный `flutter test` и Windows manual smoke должны быть зафиксированы в PR только после фактического запуска.

## Manual validation

Проверить на Windows:

- cached logged-in startup;
- sign in / logout / sign in again;
- account popup;
- System / Light / Dark + restart;
- System / Russian / English + restart;
- Yandex / Local / Matching / Missing / Downloads / Sync / Metadata Editor / Settings / Help / About;
- dark-mode readability;
- long displayName;
- Now Playing при utility navigation;
- Yandex playlist lifetime при theme/locale switch.

## Non-goals

Не входят:

- Yandex Upload / bulk upload / reverse Sync;
- mobile / Android UI;
- новый Matching engine;
- destructive Sync;
- automatic Different Version replacement;
- новый playback engine;
- state-management/routing framework;
- telemetry;
- MusicArk cloud account;
- release packaging / installer / tag / GitHub Release.

## Текущий статус реализации

Ветка является Draft v0.9.0. До принятия версии должны быть закрыты оставшиеся acceptance gaps, включая полный перенос пользовательских статических строк legacy feature pages в localization resources и фактическую автоматическую/manual validation.
